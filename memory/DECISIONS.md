## 2026-10-20 建库

- **空库起步**：只建结构骨架，不放任何示例知识，避免「示例」被当成事实。
- **路径用英文 slug，内容用中文**：`knowledge/hanzi-origin/etymology.md` 这类路径跨平台、对 git 和 URL 都安全；中文只放在标题、摘要、关键词里。
- **对外内容统一 `public`**：网页 / 微信要用的知识放在 `permission=public` 的主题下；内部资料另建 `internal` 主题，不混放。
- **问答只认 Claim**：回答用户只依据 active + public 的 Claim，没有依据就说没有，不用模型常识兜底。
- **变动走 `knowledge-plan`**：知识增删改一律通过 `pkc knowledge-plan`，先预览、再批准精确哈希、再应用。
- **汉字知识用 `fact_classes: ["evidence_scope"]`**：PKC 的 Authority Ref 面向代码契约类事实（设计意图 / 实现 / 文档契约），库里只有 8 个固定 fact class；汉字知识是文献证据型，用 `evidence_scope` 表达「以实际资料为界」，既满足校验，又不必为每条知识伪造 Authority Ref。需要严格出处时改用 `sources/` + `register-source` + `add-evidence`。

## 2026-10-20 字卡（网页）

- **字卡固定五栏、顺序不变**：字形 → 字根 → 本义 → 转义 → 衍生字义。字形图只从《系统汉语》原稿抽，其余四栏只能来自 Claim；每栏末尾必须带 `[clm_…]`，没有有效引用就显示「条目里还没有这一项」，不用模型常识兜底。
- **字根只认「从X」构形条目**：从 Claim 正文里的 `从「口」`、`从口㠯声` 抽构字成分；条目自称「X是音源字」或明说「析形不确」的不设字根；若有多个候选，优先取「知识库里有自己主题（X部）」的那个。
- **字根本身的 Claim 单独成组当证据**：和字的条目一起连续编号喂给模型，模型偷懒写 `[3]` 这种编号时，由 `sanitizeSection` 按编号表映射回 `clm_` id；映射不上或不在本次条目里的引用一律丢弃。
- **原稿的实物配图一起抽出来**：字形行下面紧跟的 `[图片]` + `▲公牛` 是实物/遗址照片，不是字形图，但主人要的是「士 = 公牛」这种直观对照，所以按「定义行 / 字族衍義里的衍生字条目」归属到对应字，存 `web/public/glyphs/photos/<字>/`，说明文字写进 `index.json`（`photos: {字: [{file, caption}]}`）。只在网页上作为字形图的补充展示，不参与字义作答。
- **没有独立字形行的字，退一步用字根的字形与配图**：原稿的字形行按「部头」排，字族成员（如「仕」之于「士」）没有自己的行。这时用 `findRoot` 找到字根，取字根的字形图与配图，并在卡片上注明「取自字根『士』」——是明确的转引，不是冒充。

## 2026-10-20 boundary 写法

- **boundary 只写出处部次**：主人要求「不需要注明『不当作学界共识』字样，只需要注明源自《系统汉语》某一部即可」，因此全库 539 条 Claim 的「适用边界」统一改为只写来源：部内条目 `源自《系统汉语》第16部「矢部」。`，卷首条目 `源自《系统汉语》卷四「弋」卷首。`，绪论 `源自《系统汉语》绪论。`，目录 `源自《系统汉语》全书目录。`。理由：库里的知识本来就是《系统汉语》的说法，逐条声明「非学界共识」是冗余；写清部次还能直接指向原书页码体系（12 章/100 卷/609 部）。
- **部次的判定口径**：按 Claim 标题的主语字对到该卷的部序号（部号与部首字取自「全书目录与结构」批）；主语是属字的继承所属部（如「知」归第16部矢部、「尺」归第17部尸部）；卷首综述类条目写卷首，不强行挂部。后续新录分卷沿用同一口径，不再逐条解释边界。
- **部号只认原文件里的编号标题**（2026-10-20 主人指正：「原文件前面的阿拉伯数字就是《系统汉语》的『部』，具体见《目录》」）：部是以原稿里 `16.矢部`、`26.弋部` 这类「数字.部首字部」标题划分的，不是靠标题主语字去猜。核对结果：卷二（8–15）、卷三（16–25）、卷四（26–33）原稿编号与《目录》完全一致；`卷一.docx` 只有 20 行卷首概述、没有任何编号部标题，故卷一 32 条全部属「卷一「雞」卷首」，原先挂到第1/2/4/6/7部的 6 条已改回（`bnd_96d0243d69ba5d4cb7a2f90d77`）。推论：以后先查该卷原稿有无编号标题，无编号的一律按卷首处理，宁少挂部不硬挂。
